# Contributing

Thank you for improving this technical reference.

## Good Contributions

- Clarify architecture decisions with diagrams or small examples.
- Label provider-confirmed behavior separately from reference architecture.
- Keep examples credential-free and safe to run in dry-run mode.
- Include tests or validation steps for configuration changes.
- Use concise commit messages that describe one documentation or example change.

## Pull Requests

Explain the problem, the proposed change, and how you verified it. Avoid claims that guarantee account safety, ranking, or uninterrupted access.
